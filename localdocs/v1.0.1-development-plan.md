# Retell CLI v1.0.1 Development Plan

## Executive Summary

This release focuses on improving token efficiency for AI agents, adding advanced filtering capabilities, and streamlining the prompt iteration workflow. All features maintain backward compatibility with v1.0.0.

---

## Development Phases

### Phase 1: Foundation & Utilities (2-3 days)

**Objective:** Build shared utilities that multiple features will depend on.

**Tasks:**
1. Create field filtering utility in `src/services/output-formatter.ts`
   - Function: `filterFields(data: any, fields: string[]): any`
   - Support dot notation for nested fields (`metadata.duration`)
   - Handle arrays and edge cases (missing fields, invalid paths)
   - Return meaningful errors for invalid field names

2. Create prompt diffing utility in `src/services/prompt-diff.ts`
   - Function: `generateDiff(local: PromptSource, remote: PromptSource): DiffResult`
   - Support both retell-llm and conversation-flow types
   - Generate structured diff output with old/new values
   - Handle file-based vs API-based prompt structures

3. Add TypeScript types for new features
   - `DiffResult` interface
   - `HotspotIssue` interface
   - `SearchOptions` interface

**Deliverables:**
- `src/services/output-formatter.ts` (enhanced)
- `src/services/prompt-diff.ts` (new)
- `src/types/index.ts` (new or enhanced)

**Testing Requirements:**
- Unit tests for `filterFields()`:
  - ✓ Top-level field selection
  - ✓ Nested field selection with dot notation
  - ✓ Multiple fields selection
  - ✓ Invalid field names (should gracefully skip or warn)
  - ✓ Array handling
  - ✓ Empty/null data handling

- Unit tests for `generateDiff()`:
  - ✓ Retell-LLM prompt changes (general_prompt, states)
  - ✓ Conversation-flow prompt changes
  - ✓ No changes scenario
  - ✓ New files vs deleted files
  - ✓ Type mismatches between local and remote

### Phase 2: Feature 1 - Field Selection (1-2 days)

**Objective:** Add `--fields` option to transcripts and agents commands for token control.

**Tasks:**
1. Add `--fields` option to transcript commands:
   - `src/commands/transcripts/list.ts`
   - `src/commands/transcripts/get.ts`
   - `src/commands/transcripts/analyze.ts`

2. Add `--fields` option to agent commands:
   - `src/commands/agents/list.ts`
   - `src/commands/agents/info.ts`

3. Integrate `filterFields()` utility into each command
4. Update command help text with field examples

**Deliverables:**
- Modified command files with --fields support
- Consistent implementation across all commands

**Testing Requirements:**
- Integration tests for each command:
  - ✓ `retell transcripts list --fields call_id,call_status`
  - ✓ `retell transcripts get <id> --fields metadata.duration,analysis`
  - ✓ `retell transcripts analyze <id> --fields call_id,performance`
  - ✓ `retell agents list --fields agent_id,agent_name`
  - ✓ `retell agents info <id> --fields agent_name,response_engine_type`
  - ✓ Nested field selection: `--fields metadata.start_time`
  - ✓ No --fields flag (should return everything - backward compat)
  - ✓ Invalid field names (graceful handling)

### Phase 3: Feature 2 - Raw Output Mode (1 day)

**Objective:** Add `--raw` flag to return unmodified API responses.

**Tasks:**
1. Modify `src/commands/transcripts/analyze.ts`
   - Add `--raw` boolean flag
   - When set, return `client.call.retrieve()` directly

2. Consider extending to other commands if beneficial
   - Agents commands
   - Other transcript commands

**Deliverables:**
- `src/commands/transcripts/analyze.ts` with --raw support

**Testing Requirements:**
- ✓ `retell transcripts analyze <id> --raw` returns unmodified API response
- ✓ Default behavior (no --raw) returns enriched analysis
- ✓ --raw works with --fields (apply field filtering to raw response)
- ✓ Raw response matches Retell API schema exactly
- ✓ Error handling when API returns errors

### Phase 4: Feature 5 - Hotspots Detection (2 days)

**Objective:** Add `--hotspots-only` view to identify conversation issues.

**Tasks:**
1. Research Retell API response structure
   - Identify available metrics (latency, interruptions, sentiment)
   - Document what's available in API vs what requires calculation

2. Implement hotspot detection logic in `src/commands/transcripts/analyze.ts`
   - Latency spike detection (p90 > threshold, e.g., 2000ms)
   - Interruption detection (from API metadata)
   - Sentiment markers (if available)
   - Long silence detection (timestamp gaps > threshold)

3. Add `--hotspots-only` flag
   - Return structured hotspots array
   - Include turn_index, timestamp, issue_type, utterances, metrics

4. Define configurable thresholds (optional)
   - Could be hardcoded initially
   - Future: allow `--latency-threshold 2000`

**Deliverables:**
- Enhanced `src/commands/transcripts/analyze.ts` with hotspot detection
- Hotspot detection helper functions

**Testing Requirements:**
- ✓ Detect latency spikes (p90 > 2000ms)
- ✓ Detect interruptions in transcript
- ✓ Detect long silences (> 5s gaps)
- ✓ Return empty hotspots array if none found
- ✓ Hotspots include correct turn_index and timestamps
- ✓ Works with --fields (e.g., `--hotspots-only --fields call_id,hotspots`)
- ✓ Error handling when metrics unavailable
- ✓ Test with various call scenarios (normal, problematic, edge cases)

### Phase 5: Feature 3 - Transcripts Search Command (2-3 days)

**Objective:** Create dedicated search command with hybrid filtering.

**Tasks:**
1. Research Retell SDK `call.list()` capabilities
   - Document supported query parameters
   - Identify what can be passed to API vs client-side filtering

2. Create `src/commands/transcripts/search.ts`
   - Options: --status, --agent-id, --since, --until, --limit
   - Parse date inputs (ISO format, relative dates)
   - Implement hybrid filtering strategy

3. Implement filtering logic:
   - **API-level:** Pass supported params to `client.call.list()`
   - **Client-side:** Filter remaining params locally
   - Document which filters are API vs client-side

4. Register command in `src/index.ts`

**Deliverables:**
- `src/commands/transcripts/search.ts` (new)
- Updated `src/index.ts` with new subcommand
- Documentation of filter capabilities

**Testing Requirements:**
- ✓ `retell transcripts search --status error`
- ✓ `retell transcripts search --agent-id agent_123`
- ✓ `retell transcripts search --since 2025-11-01 --until 2025-11-15`
- ✓ Combined filters: `--status error --agent-id agent_123`
- ✓ Limit results: `--limit 10`
- ✓ Date parsing (ISO dates, edge cases)
- ✓ Empty results (no matches)
- ✓ Works with --fields for token efficiency
- ✓ Returns structured `{results: [...]}` format
- ✓ Error handling for invalid dates, statuses, agent IDs

### Phase 6: Feature 4 - Diff Command & Dry Run (3-4 days)

**Objective:** Add diff inspection and dry-run capabilities for prompt updates.

**Tasks:**
1. Create `src/commands/prompts/diff.ts`
   - Accept agent-id as argument
   - Fetch remote prompts via `resolvePromptSource()`
   - Load local prompts from `.retell-prompts/<agent-id>/`
   - Use `generateDiff()` utility
   - Output structured diff with old/new values

2. Enhance `src/commands/prompts/update.ts`
   - Add `--dry-run` flag
   - When set, show diff without applying
   - Reuse diff logic from diff command
   - Show confirmation prompt or summary

3. Register diff command in `src/index.ts`

4. Handle edge cases:
   - Agent type mismatches
   - Missing local or remote files
   - No changes scenario

**Deliverables:**
- `src/commands/prompts/diff.ts` (new)
- Enhanced `src/commands/prompts/update.ts`
- Updated `src/index.ts`

**Testing Requirements:**
- **Diff command:**
  - ✓ `retell prompts diff <agent-id>` shows changes
  - ✓ Works with retell-llm agents
  - ✓ Works with conversation-flow agents
  - ✓ Shows "no changes" when local matches remote
  - ✓ Handles new files (not in remote)
  - ✓ Handles deleted files (not in local)
  - ✓ Shows section-level changes (states, nodes)

- **Dry-run:**
  - ✓ `retell prompts update <agent-id> --dry-run` shows diff
  - ✓ Does NOT apply changes when --dry-run is set
  - ✓ Returns same diff structure as diff command
  - ✓ Works with --source flag

- **Edge cases:**
  - ✓ Error when `.retell-prompts/<agent-id>/` doesn't exist
  - ✓ Error when agent not found in API
  - ✓ Error when type mismatch (local vs remote)
  - ✓ Handles large diffs gracefully

## Risk Assessment

| Risk | Impact | Mitigation |
|------|--------|------------|
| Retell API doesn't support search params | Medium | Client-side filtering works, just slower |
| Hotspot metrics not available in API | Medium | Start with basic heuristics, enhance later |
| Breaking changes in output format | High | Use flags (--raw, --fields) to opt-in to changes |
| Large diff performance issues | Low | Implement streaming or pagination if needed |
| Field selection complex edge cases | Medium | Comprehensive testing, graceful degradation |
